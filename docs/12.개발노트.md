
**증상**:
1. **히어로 섹션** (상단 배너 👥 아이콘): 빈 값 표시 (`<span></span>`)
2. **사이드바** (🎫 신청 정보): "무제한"만 표시, 현재 0명인지 알 수 없음
3. **사용자 경험**: 무제한 강의에서 현재 신청 인원 정보 완전 손실

**데이터베이스 상태**:
- `lecture_id: 226`
- `registration_count: 0` (표시 안 됨)
- `max_participants: NULL` ("무제한"만 표시)

### 🔍 근본 원인 분석 (Ultra Think 7단계)

#### 1단계: 문제 정의
- 무제한 강의에서 현재 신청 인원 정보 손실
- "무제한"만 표시되어 사용자가 몇 명이 신청했는지 알 수 없음

#### 2단계: 데이터 수집 (Agent 조사)
**두 곳 문제 발견**:
1. **히어로 섹션**: `detail.php` Line 132 → `<?= $lecture['capacity_info'] ?>`
2. **사이드바**: `detail.php` Lines 724-730 → 조건문에서 `registration_count` 무시

**Agent 조사 결과**:
- `capacity_info` 변수가 `LectureController::show()` 메서드에서 생성되지 않음
- `getLectureById()` SQL 쿼리는 `registration_count`와 `max_participants`만 조회
- 사이드바 PHP 조건문은 `max_participants` NULL일 때 "무제한"만 출력

#### 3단계: 근본 원인

**스크린샷**: `/temp/screenshots/screenshot_20251116_201301.png`

**원인 분석**:
```css
.lecture-grid {
    grid-template-columns: repeat(auto-fit, minmax(400px, 1fr));
}
```
- `auto-fit`: 빈 트랙을 축소하지만, 남은 공간은 기존 아이템에게 배분
- `minmax(400px, 1fr)`: 최소 400px, 최대 `1fr` (남은 공간 전체)
- **결과**: 1개 카드가 있을 때 `1fr`이 컨테이너 전체 너비를 차지
- 1200px 컨테이너에 1개 카드 → 1200px 너비로 늘어남 (과도함)

### ✅ 해결

**수정 코드**:
```css
.lecture-card {
    background: white;
    border-radius: 12px;
    overflow: hidden;
    box-shadow: 0 4px 6px rgba(0, 0, 0, 0.05);
    border: 1px solid #e2e8f0;
    transition: all 0.2s ease;
    max-width: 500px; /* 1개 카드가 전체 너비 차지하는 것 방지 */
}
```

**개선 효과**:
- ✅ 1개 카드: 최대 500px 너비 유지 (좌측 정렬)
- ✅ 2개 카드: 각각 적절한 너비로 나란히 표시
- ✅ 3개 이상: Grid 자동 배치 (400px ~ 500px 사이)
- ✅ 반응형: 모바일에서는 1개 컬럼으로 자동 전환 (기존 미디어 쿼리)

### 📁 수정 파일

- **dashboard.php** (Line 129)
  - `.lecture-card`에 `max-width: 500px` 추가 (1줄)

### 🎓 기술적 교훈

**CSS Grid의 auto-fit vs auto-fill**:
- `auto-fit`: 빈 트랙 축소 후 남은 공간을 기존 아이템에 배분
- `auto-fill`: 빈 트랙 유지 (공간이 있으면 빈 트랙 생성)

**이번 케이스**:
- `auto-fit`은 올바른 선택 (빈 공간 축소)
- 문제는 `1fr`이 무제한 늘어남
- 해결: 아이템 자체에 `max-width` 설정

#### 2️⃣ 근본 원인 파악
**파일**: `src/models/Post.php:222-252` (`getListWithOffset()` 메서드)

```php

SELECT ...
FROM (
    SELECT ... FROM posts
    WHERE status = 'published'
    ORDER BY created_at DESC    -- 서브쿼리에만 ORDER BY
    LIMIT ? OFFSET ?
```

**MySQL 동작 원리**:
- 서브쿼리의 ORDER BY는 외부 쿼리에 **보장되지 않음**
- MySQL 공식 문서: "Subquery ORDER BY is ignored unless combined with LIMIT"
- 서브쿼리 + LIMIT는 내부적으로만 정렬
- JOIN 연산 후 순서가 무작위로 섞임

#### 3️⃣ 해결 방법

```php
// ✅ 수정 코드
SELECT ...
FROM (
    SELECT ... FROM posts
    WHERE status = 'published'
    ORDER BY created_at DESC, id DESC    -- 1차 정렬 (서브쿼리)
    LIMIT ? OFFSET ?
) p
JOIN users u ON p.user_id = u.id
ORDER BY p.created_at DESC, p.id DESC   -- 2차 정렬 (외부 쿼리) ✅
```

**핵심 개선 사항**:
1. 서브쿼리에 `id DESC` 추가 (동일 created_at 시 정렬 보장)
2. **외부 쿼리에 `ORDER BY p.created_at DESC, p.id DESC` 추가** (핵심!)

### 🔍 근본 원인 분석

**무한 재귀 루프 발생 메커니즘**:

```javascript
// ❌ 문제 코드 (v3.90.9)
function renderChatRoomItem(roomId, roomData) {
    // ...
    if (!users[otherUserId]) {
        loadUserInfo(otherUserId).then(() => {
            renderChatRoomItem(roomId, roomData); // ← 자기 자신을 재호출!
        });
    }
}

async function loadUserInfo(userId) {
    if (!userId || users[userId]) {
        return Promise.resolve(); // ← users[userId] 있으면 early return
    }
    // API 호출...
}
```

**문제 흐름**:
1. `renderChatRoomItem(roomId, roomData)` 호출
2. `users[otherUserId]` 없으면 `loadUserInfo()` 호출
3. `loadUserInfo()` 완료 후 `renderChatRoomItem()` 재호출
4. `users[otherUserId]`는 존재하지만 `nickname`이 없음
5. `shouldRefreshProfile` 조건에 의해 다시 `loadUserInfo()` 호출 시도
6. 하지만 `loadUserInfo()`는 `users[userId]` 존재 시 즉시 `return`
7. **무한 재귀 루프 발생!** → 페이지 멈춤

### ✅ 해결 방법

**1. 재귀 호출 완전 제거**
```javascript
// ✅ 수정 후 (v3.91.0)

```
