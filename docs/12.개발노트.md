## 🔥 2025-11-15: 기업 회원 탈퇴 에러 메시지 완전 개선 (v3.98.14)

**작성일**: 2025-11-15
**버전**: v3.98.14
**담당**: Claude (Anthropic)
**작업 모드**: Ultra Think 모드 - 3단계 근본 원인 분석

### 📌 주요 성과

**4가지 버그 완전 해결**:
1. **기업 회원 메뉴 권한 버그** - `null !== false` 버그 수정
2. **탈퇴 에러 메시지 개선** - 강의/행사 개수 구체적 표시

4. **CSP 에러** - cdnjs.cloudflare.com 차단 해제

### 🐛 버그 1: 기업 회원 신청 관리 메뉴 권한 버그 (치명적)

**증상**:
- `corp_status = 'pending'` 사용자에게도 "신청 관리" 메뉴 표시
- 승인되지 않은 사용자가 권한 획득

**근본 원인**:
```php
// CorporateMiddleware.php Line 50
$result = $db->fetch($sql, [$_SESSION['user_id']]);
return $result !== false;  // ❌ Bug: null !== false = true
```
- `Database::fetch()`는 결과 없을 때 `null` 반환 (not `false`)
- PHP에서 `null !== false`는 `true`로 평가됨

**해결**:
```php
return !empty($result);  // ✅ Fix: !empty(null) = false
```

**수정 파일**:
- `src/middlewares/CorporateMiddleware.php` (Line 50)

### 🐛 버그 3: 프론트엔드 메시지 표시 완전 수정 (3단계 근본 원인 분석)

**증상**:
- 백엔드는 정확한 메시지 반환
- Toast에는 "회원탈퇴 처리 중 오류가 발생했습니다" 일반 메시지만 표시

**근본 원인 분석 (3단계)**:

1. **1차 원인**: 빈 문자열 필터링 실패
   ```json
   {
       "status": "error",
       "data": { "message": "등록된 강의 3개..." },
       "message": ""  // ← 빈 문자열!
   }
   ```

2. **2차 원인**: ApiClient가 400 오류에서 throw
   ```javascript
   // api-client.js.php Line 345-347
   if (!response.ok) {
       await this.handleHttpError(response, options);  // throw 발생!
   }
   ```

3. **최종 원인**: `.catch()` 블록으로 이동하여 일반 메시지 표시

**해결 방법**:
```javascript
// edit.php Lines 1472-1519
// ApiClient 대신 fetch 직접 사용
fetch('/api/user/delete-account', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ password, reason, csrf_token })
})
.then(response => response.json())  // ✅ HTTP 상태 무관하게 파싱
.then(data => {
    // ✅ 빈 문자열 필터링 + data.data.message 우선
    const message = (data.data && data.data.message)
        || (data.message && data.message.trim())
        || '회원탈퇴 처리에 실패했습니다.';

    Toast.error(message);  // ✅ 정확한 메시지 표시
});
```

**수정 파일**:
- `src/views/user/edit.php` (Lines 1472-1519)

#### 2️⃣ 근본 원인 파악 - ApiClient.delete() 메서드 시그니처 불일치

**ApiClient.delete() 실제 시그니처** (`src/views/includes/api-client.js.php:413-415`):

async delete(url, options = {}) {

#### 2️⃣ 근본 원인 파악
**파일**: `src/models/Post.php:222-252` (`getListWithOffset()` 메서드)

```php
// ❌ 문제 코드
SELECT ...
FROM (
    SELECT ... FROM posts
    WHERE status = 'published'
    ORDER BY created_at DESC    -- 서브쿼리에만 ORDER BY
    LIMIT ? OFFSET ?

```

**MySQL 동작 원리**:
- 서브쿼리의 ORDER BY는 외부 쿼리에 **보장되지 않음**
- MySQL 공식 문서: "Subquery ORDER BY is ignored unless combined with LIMIT"
- 서브쿼리 + LIMIT는 내부적으로만 정렬
- JOIN 연산 후 순서가 무작위로 섞임

#### 3️⃣ 해결 방법

```php
// ✅ 수정 코드
SELECT ...
FROM (
    SELECT ... FROM posts
    WHERE status = 'published'
    ORDER BY created_at DESC, id DESC    -- 1차 정렬 (서브쿼리)
    LIMIT ? OFFSET ?
) p
JOIN users u ON p.user_id = u.id
ORDER BY p.created_at DESC, p.id DESC   -- 2차 정렬 (외부 쿼리) ✅
```

**핵심 개선 사항**:
1. 서브쿼리에 `id DESC` 추가 (동일 created_at 시 정렬 보장)
2. **외부 쿼리에 `ORDER BY p.created_at DESC, p.id DESC` 추가** (핵심!)
