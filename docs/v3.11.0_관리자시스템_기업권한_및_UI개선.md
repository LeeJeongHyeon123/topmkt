**발견된 3가지 핵심 문제**:

1. **AdminController 권한 값 불일치**:
   ```php
   // 문제: 첫 번째 위치
   $allowedRoles = ['ROLE_USER', 'ROLE_CORP', 'ROLE_ADMIN'];  // ❌
   
   // 해결: 통일

   ```

2. **User 모델 updateProfile 메서드 필드 누락**:
   ```php
   // 문제: role, status 필드가 allowedFields에 없음
   $allowedFields = [
       'nickname', 'email', 'phone', 'bio', 'birth_date', 'gender', 
       'website_url', 'social_links',  // role, status 누락 ❌
       'profile_image_original', 'profile_image_profile', 'profile_image_thumb'
   ];
   
   // 해결: role, status 추가
   $allowedFields = [
       'nickname', 'email', 'phone', 'bio', 'birth_date', 'gender', 
       'website_url', 'social_links', 'role', 'status',  // ✅ 추가
       'profile_image_original', 'profile_image_profile', 'profile_image_thumb'
   ];
   ```

3. **데이터베이스 ENUM 제약**:
   ```sql
   -- 문제: ROLE_CORPORATE 값이 ENUM에 없음
   role enum('ROLE_USER','ROLE_CORP','ROLE_ADMIN')  -- ❌
   
   -- 해결: ROLE_CORPORATE 추가
   ALTER TABLE users MODIFY COLUMN role 
   ENUM('ROLE_USER','ROLE_CORP','ROLE_CORPORATE','ROLE_ADMIN') DEFAULT 'ROLE_USER';  -- ✅
   ```

### 2. CSRF 토큰 시스템 완성

#### 문제
- `generateCsrfToken()` 메서드 누락
- `logUserActivity()` 메서드 누락으로 인한 500 에러

#### 해결
```php
/**
 * CSRF 토큰 생성
 */
private function generateCsrfToken() {
    if (session_status() === PHP_SESSION_NONE) {
        session_start();
    }
    
    if (!isset($_SESSION['csrf_token'])) {
        $_SESSION['csrf_token'] = bin2hex(random_bytes(32));
    }
    
    return $_SESSION['csrf_token'];
}

/**
 * 관리자 활동 로깅
 */
private function logUserActivity($adminId, $action, $details, $metadata = []) {
    try {
        $logMessage = "[ADMIN_LOG] Admin ID: {$adminId}, Action: {$action}, Details: {$details}";
        if (!empty($metadata)) {
            $logMessage .= ", Metadata: " . json_encode($metadata);
        }
        error_log($logMessage);
    } catch (Exception $e) {
        error_log("Admin activity logging failed: " . $e->getMessage());
    }
}
```

## 📊 계정 상태별 동작 완전 분석

### 상태별 기술적 동작

| 상태 | 전화번호 조회 | 로그인 시도 | 페이지 접근 | 실제 결과 |
|------|-------------|------------|------------|-----------|
| **active** | ✅ | ✅ | ✅ | **완전 허용** |
| **inactive** | ✅ | ✅ | ❌ | **로그인 후 즉시 차단** |
| **suspended** | ✅ | ✅ | ❌ | **로그인 후 즉시 차단** |
| **deleted** | ❌ | ❌ | ❌ | **로그인조차 불가** |

### 상태별 의미

1. **active**: 정상 사용 가능한 활성 계정
2. **inactive**: 비징계적 일시 정지 (휴면, 본인 요청 등)
3. **suspended**: 징계적 정지 (관리자 조치, 규칙 위반 등)  
4. **deleted**: 완전 삭제된 계정 (복구 불가)

### 핵심 발견사항

- `inactive`와 `suspended`는 **기술적으로 동일하게 작동**
- 둘 다 로그인은 성공하지만 AuthMiddleware에서 즉시 차단
- 관리적 의미와 향후 처리 방침에서 차이를 가짐
