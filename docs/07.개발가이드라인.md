## 1. 코딩 스타일 가이드

### 🔧 1.1 일반 규칙
- **버전 관리:** Git 사용 (GitHub Flow)
- **인코딩:** 모든 파일은 UTF-8 (BOM 없음)
- **들여쓰기:** 4 스페이스, 탭 금지
- **최대 줄 길이:** 120자 (PSR-12 기준)
- **줄 끝:** Unix 스타일 LF (`\n`)

### 💻 1.2 PHP 스타일 가이드
- **표준:** PSR-12 코딩 표준 준수
- **파일 헤더:**
  - `<?php` 태그 다음 줄에 한 줄 공백
  - 파일 마지막은 개행으로 끝나야 함
- **네임스페이스 & use**
  - 네임스페이스 선언 다음에는 한 줄 공백
  - `use` 구문은 그룹화
- **클래스 & 메서드**
  - 클래스명: PascalCase
  - 메서드명: camelCase
  - 접근 제한자 항상 명시 (`public`, `protected`, `private`)
  - 메서드와 메서드 사이에는 한 줄 공백

**예시:**
```php
<?php

namespace App\Controllers;

use App\Models\User;
use App\Helpers\ResponseHelper;

class UserController extends BaseController
{
    public function index(): void
    {
        $users = User::all();
        ResponseHelper::success($users);
    }
}
```

### 🌐 1.3 HTML/CSS/JavaScript 가이드

#### HTML
- **문서 구조:** `<!DOCTYPE html>`, `<html lang="ko">`, `<head>`, `<body>`
- **들여쓰기:** 2 스페이스(HTML), 4 스페이스(PHP 템플릿)
- **속성 순서:** `id`, `class`, `src`, `href`, `alt`, `title`, `role`, `aria-*`

#### CSS
- **네이밍:** BEM(Block__Element--Modifier) 규칙 사용
- **들여쓰기:** 2 스페이스
- **단위:** `rem` 우선, 필요 시 `px`, `em` 사용

#### JavaScript
- **ES6 모던 문법** 사용 (`let`, `const`, 템플릿 문자열, arrow function 등)
- **들여쓰기:** 4 스페이스
- **세미콜론:** 필수 (`;`)
- **따옴표:** 작은따옴표(`'`) 사용
- **비동기 처리:** `async` / `await` 사용 권장

**예시:**
```javascript
// ✅ 좋은 예
const fetchUsers = async () => {
    try {
        const users = await ApiClient.get('/api/users');
        Toast.success('사용자 목록을 불러왔습니다.');
        return users;
    } catch (error) {
        Toast.error('사용자 목록을 불러오는데 실패했습니다.');
        WebLogger.error('Failed to fetch users', { error });
    }
};

// ❌ 나쁜 예
function fetchUsers() {
    fetch("/api/users").then(function(response) {
        return response.json()
    }).then(function(users) {
        alert("Success")
    })
}
```

### 📝 1.4 네이밍 규칙

| 대상 | 규칙 | 예시 |
|------|------|------|
| **파일/디렉토리** | 소문자, 하이픈(`-`) | `user-controller.php`, `auth-middleware.php` |
| **클래스** | PascalCase | `UserController`, `PostModel` |
| **메서드/함수** | camelCase | `getUserById()`, `createPost()` |
| **변수** | camelCase | `$userId`, `$postCount` |
| **상수** | UPPER_SNAKE_CASE | `MAX_UPLOAD_SIZE`, `DB_HOST` |
| **테이블명/컬럼명** | snake_case | `user_profiles`, `created_at` |
| **CSS 클래스명** | kebab-case | `btn-primary`, `card-header` |

### 🔒 3.2 보안 코딩 원칙

#### 핵심 보안 규칙
- **SQL Injection 방어**: Prepared Statements 필수
- **XSS 방어**: `htmlspecialchars()` 사용
- **CSRF 방어**: 모든 POST/PUT/DELETE 요청에 CSRF 토큰 검증
- **인증**: AuthMiddleware로 인증 필수 페이지 보호
- **파일 업로드**: 확장자, 크기 검증 필수

**예시:**
```php
// ✅ 좋은 예 - Prepared Statements
$stmt = $db->prepare("SELECT * FROM users WHERE email = ?");
$stmt->execute([$email]);

// ❌ 나쁜 예 - SQL Injection 취약
$result = $db->query("SELECT * FROM users WHERE email = '$email'");
```

**상세 문서:** [17.보안_가이드.md](./17.보안_가이드.md)

### ⚡ 3.3 성능 최적화 원칙

#### 핵심 최적화 전략
- **인덱스 활용**: 자주 조회되는 컬럼에 인덱스 설정
- **캐싱 시스템**: CacheHelper, PageCacheHelper 활용
- **쿼리 최적화**: SELECT 컬럼 명시, N+1 쿼리 방지
- **이미지 최적화**: 자동 리사이징, WebP 지원
- **브라우저 캐싱**: 정적 파일 캐시 헤더 설정

**예시:**
```php
// ✅ 좋은 예 - 캐싱 활용
$users = CacheHelper::remember('users:all', 3600, function() {
    return User::all();
});

// ❌ 나쁜 예 - 매번 DB 조회
$users = User::all();
```

**상세 문서:** [21.성능_최적화_가이드.md](./21.성능_최적화_가이드.md)

### 📊 3.4 로깅 및 에러 처리

#### WebLogger 사용 원칙
- **info**: 정상 동작 기록
- **warning**: 경고 (알림 스킵 등)
- **error**: 오류 (예외, API 오류 등)

**예시:**
```php
// 성공 로깅
WebLogger::info('FCM 푸시 알림 전송 완료', [
    'recipient_id' => $userId,
    'sent_count' => $sentCount
]);

// 오류 로깅
WebLogger::error('FCM 푸시 알림 전송 실패', [
    'recipient_id' => $userId,
    'error' => $exception->getMessage()
]);
```

#### ResponseHelper 사용 원칙
```php
// 성공 응답
ResponseHelper::success($data, '성공 메시지');

// 오류 응답

```
